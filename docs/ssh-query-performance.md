# SSH 声明式查询性能优化

## 2026-10-12：开发环境对照验证

交易列表仅需返回一页，但原配置 `ordered: false` 会扫描整个累计汇总文件，在时间过滤前执行 JSON 感知的字段拆分及全部映射。现场文件约 7 MB、2.4 万行，覆盖 2026-07-22 至 2026-10-12；枚举只有约 12 个目录项，瓶颈主要为记录解析，而非文件发现。

本次修改：

- 时间字段使用正则时，先提取、归一化并过滤时间，再拆分其他字段；索引时间字段保持原流程。
- 字段正则在一次远程查询内预编译复用。有序定位也避免不必要的字段拆分。
- 本地开发配置仅将已验证的交易列表规则的 `ordered` 从 `false` 改为 `true`；其他规则及其他环境不变。此配置不在 Git 中，其他设备需要单独同步。
- 保留扫描预算、范围提示、分页排序和乱序处理，不以隐藏警告或丢弃历史数据提速。

验证：SSH 回归 14 项通过，包含乱序记录、开始包含/结束排除边界、字段索引/正则等价、有序历史区间、JSON 内竖线、中文、多行及同时间戳分页。

远程只读对照使用固定的已结束 24 小时窗口，避免活跃文件追加影响比较。原脚本 22,434 ms，时间预过滤版本（仍无序）2,210 ms，新版本及有序配置 3,844 ms；三组返回的 501 条记录，所有字段及顺序一致。连接与远端负载有波动，此数据不是性能承诺，也不是桌面安装包验收。

仅对现场有效时间戳未出现倒序的该汇总规则启用有序读取，不能自动将所有环境标记为有序。
# 快照游标分页（2026-10-12）

SSH 声明式交易汇总查询现在支持会话内续读，Web、桌面及桌面 LAN 共用同一远程采集脚本。

- 首页每次查询生成新 sessionId；查询条件、应用、环境、每页条数变化也重建会话。ELK 不使用此机制。
- 快照固定匹配文件清单、各文件 inode/device、最后一个完整记录边界及边界校验片段。会话内忽略后续追加内容，也不会切换到新产生的“最新文件”。
- 从尾部按 64 KiB 分块向文件头读取。每个文件先找到 pageSize+1 条匹配记录，再向前额外检查 64 条物理记录；相同边界时间戳的记录继续读取，避免同毫秒记录排序跨页变化。
- 所有字段筛选在决定“够一页”之前执行。跨过开始时间后再检查 64 条记录，容忍边界附近的小范围乱序；不是任意乱序的正确性保证。用户确认汇总文件时间有序，此假设仅用于汇总分页，不用于应用日志或交易事件聚合。
- 服务端按服务器保留文件游标和未展示候选记录，合并排序后沿用现有分页响应；后续翻页只补读新的部分。每个未读完文件均已积累足够候选时，直接使用缓冲，不再发起 SSH 命令。返回上一页复用会话数据，返回首页重建快照。
- 文件删除、轮转、截断、边界内容改写会明确要求重新查询首页，不静默换文件。查询会话空闲 15 分钟过期，最多保留 8 个会话，每会话候选缓存上限 16 MiB。配置变更、跳页、并发提交冲突均显式拒绝。
- 读取预算为每台服务器每次 64 MiB，输出沿用 16 MiB 上限。达到限制抛出明确错误，不误报为没有下一页。既有 10,000 条交互深度限制、导出流程保持不变。
- 未配置声明式汇总规则、仅有 transactionEvent 聚合规则、非换行记录源仍走既有兼容查询；本次不改其解析语义。快照模式只读主汇总规则，不以 fallback 交易明细代替汇总列表。

开发环境实测：固定已结束的 24H 窗口，每页 50 条，原路径查询前 151 条用时 2720 ms；快照首页、第二页、第三页分别 565 / 584 / 579 ms。第三页累计候选前 151 条与原查询字段和顺序完全一致。该测量反映此次网络和服务器负载，不是性能承诺。没有改动远程文件或正式环境配置。

增加缓冲复用后再次对比连续五页：原路径前 251 条为 2716 ms，新会话各页为 685 / 1 / 487 / 3 / 522 ms。失败交易筛选也对比五页，各页为 645 / 606 / 587 / 572 / 509 ms；两种筛选累计 251 条的每页前缀、最终字段及顺序均与原路径相同。稀疏筛选每批需扫描更多物理行，因此不一定命中缓冲。
